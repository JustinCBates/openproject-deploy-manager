# Architecture Decision Record: Runtime Output Directories

**Date**: October 15, 2025  
**Status**: ✅ IMPLEMENTED  
**Affected Repos**: deploy-manager, control-flow  
**Issue**: Duplicate `phases/` directory confusion  

## Problem Statement

Phase orchestrators in deploy-manager were creating output directories at:
```
/opt/openproject/external/deploy-manager/phases/
```

This created a collision with the source code directory:
```
/opt/openproject/external/deploy-manager/src/phases/
```

**Confusion**: Two directories named "phases" - one for source code, one for runtime outputs.

## Root Cause

All phase orchestrators used this pattern:
```python
self.phase_dir = project_root / "phases" / f"phase_{N}_{name}"
```

Where `project_root` pointed to `/opt/openproject/external/deploy-manager/`, not `src/`.

This pattern was generated by control-flow's scaffolder template.

## Decision

**Use a dedicated `runtime/` directory for all phase outputs.**

### New Directory Structure

```
project-root/
├── src/                           ← Source code (version controlled)
│   └── phases/                    ← Phase orchestrators (Python files)
│       ├── phase_1_preflight/
│       │   ├── __init__.py
│       │   └── phase_1_preflight_orchestrator.py
│       └── ...
│
└── runtime/                       ← Runtime outputs (gitignored)
    ├── phase_1_preflight/
    │   └── outputs/
    ├── phase_2_template_rendering/
    │   └── outputs/
    │       ├── Caddyfile
    │       └── docker-compose.override.yml
    ├── phase_3_snapshot/
    │   └── outputs/
    │       ├── snapshots/snap_*.json
    │       └── config_backup_*/
    └── phase_4_deployment/
        └── outputs/
            └── .env.development
```

### New Orchestrator Pattern

```python
class PhaseOrchestrator:
    def __init__(self, project_root: Path, config: Dict[str, Any]):
        self.project_root = project_root
        self.config = config
        
        # Runtime directory for outputs
        self.phase_dir = project_root / "runtime" / f"phase_{N}_{name}"
        self.outputs_dir = self.phase_dir / "outputs"
        
        # Auto-create outputs directory
        self.outputs_dir.mkdir(parents=True, exist_ok=True)
```

## Benefits

| Benefit | Description |
|---------|-------------|
| **No collisions** | `src/phases/` for code, `runtime/` for outputs - zero ambiguity |
| **Clear semantics** | "runtime" explicitly indicates ephemeral data |
| **Simple .gitignore** | One rule: `/runtime/` |
| **Easy cleanup** | `rm -rf runtime/` removes all outputs safely |
| **IDE friendly** | IDE won't index output files in runtime/ |
| **Explicit separation** | Code vs data distinction enforced by structure |

## Migration Guide

### For Existing Projects

1. **Move outputs**:
   ```bash
   mv phases runtime
   ```

2. **Update orchestrators**:
   ```python
   # Old:
   self.phase_dir = project_root / "phases" / "phase_X"
   
   # New:
   self.phase_dir = project_root / "runtime" / "phase_X"
   ```

3. **Create .gitignore**:
   ```gitignore
   # Runtime output directories
   /runtime/
   /phases/    # Legacy - keep for safety
   
   # Python
   __pycache__/
   *.py[cod]
   ```

4. **Test**:
   ```bash
   python test_integration_full.py
   # Verify outputs appear in runtime/ not phases/
   ```

### For New Projects

Projects scaffolded with **control-flow v2.0+** automatically use `runtime/`.

No manual changes needed.

## Alternatives Considered

### Option A: Keep using `phases/`
- ❌ Rejected: Naming collision with `src/phases/`
- ❌ Confusing: Which "phases" is which?

### Option B: Use `outputs/`
- ⚠️ Considered but rejected
- Less descriptive than "runtime"
- Doesn't emphasize ephemeral nature
- "outputs" could mean permanent artifacts

### Option C: Use `src/phases/phase_X/outputs/`
- ❌ Rejected: Mixes code and runtime data
- ❌ Complex .gitignore rules: `src/phases/*/outputs/`
- ❌ Harder to clean all outputs
- ❌ IDE may index output files
